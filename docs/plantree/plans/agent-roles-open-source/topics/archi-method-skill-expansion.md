# Archi Method Skill Expansion

Date: 2026-07-10
Updated: 2026-07-22

## Purpose

Expand `agentroles.archi` so it remains a professional, reproducible
architecture reviewer when Architec is unavailable. Architec/Hippo remains one
optional evidence route, not the Role's primary dependency.

## Coverage Decision

The existing Archi surface already covered evidence selection, diff review,
full baseline review, goal-driven advice, and vendored review workflows. The
gap was not another broad review skill; it was repeatable methods for distinct
architecture concerns:

- dependency topology, cycles, and dependency direction;
- module boundaries, layering, and domain leakage;
- architecture fitness functions and guardrails;
- ADR/decision consistency and assumption drift;
- change impact, blast radius, migration, and reversibility;
- distributed-system dataflow, failure modes, and reliability tradeoffs.

These capabilities remain inside one `agentroles.archi` Role because they share
the same review-only architecture identity, permission posture, and Host
Adapter expectations.

## Source Treatment

New method skills are original synthesized Role source. External sources such
as ArchUnit, dependency-cruiser, Semgrep, CodeQL, C4, ADR/MADR tooling, AWS
Reliability guidance, and OpenTelemetry docs are recorded as provenance in
`roles/archi/references/architecture-toolbox.md`; no external examples, rules,
templates, generated artifacts, secrets, or runtime state are copied.

## Implementation Scope

- Bump `agentroles.archi` from `0.4.0` to `0.5.0`.
- Add focused `archi-*` method skills.
- Keep `network=false`, `write_files=false`, and CCB Architec `required=false`.
- Add `tests/evaluation.toml` with capability, degraded, boundary, and
  regression cases.
- Keep `roles/archi` and `reference_roles/archi` source-synchronized.
- Update formal catalog README entries and focused Archi tests.
